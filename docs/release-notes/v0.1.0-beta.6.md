## 修复（Fixes）

- **通知权限没有及时申请**：以前只有登录成功、连上服务器之后才会向 macOS 申请通知权限；如果打开时没联网或还没登录，就一直不会问。申请失败的原因也只写进日志，界面上看不出来。现在程序一打开就申请：新安装或更新后启动时，macOS 会立刻弹出"允许通知"的提示，点一次"允许"即可（macOS 不允许程序自己给自己开权限，这一步必须由你点）。每次切回程序都会重新读取权限状态，申请或发送通知失败时会在设置里显示原因。
- **上传图片失败（"could not communicate with the Zulip server: error sending request"）**：程序给上传设了 30 秒的"等待回应"上限，但这个计时从开始发送文件就算起，所以文件稍大或网速慢、30 秒内传不完的图片一定会失败。现在上传不再受这个限制（最长允许 10 分钟），出错时会写明具体原因（比如超时、连接被断开），不再只有一句"error sending request"。
- **上传失败的提示关不掉、Retry 点不了**：上传状态以前是全局的，在一个会话里失败后，每个会话的输入框上都会显示这条错误；在别的会话里点 Retry 会被拒绝，看起来就像点不了。现在错误只显示在发起上传的那个会话里，Retry 是一个明显的按钮，旁边加了关闭按钮；鼠标停在错误上可以看到完整内容。

## 新功能（New features）

- **设置里新增"通知"栏**（菜单 Zulip Mac › Settings，或 ⌘,）：
  - 显示当前权限：已允许、尚未申请、样式设成了"无"、或在系统设置里被关闭。
  - "Allow Notifications"（尚未申请时出现）：重新弹出系统的允许提示。
  - "Open System Settings"：直接打开系统设置里 Zulip Mac 的通知页面。
  - "Send Test Notification"：发一条测试通知，确认能收到。
- **链接预览卡片（像 iMessage 那样）**：单独发的一条链接会显示成卡片，有图片、标题、简介和网站名，点卡片打开网页，右键可以复制链接。服务器已经生成了预览（组织设置里开了"显示链接网站的预览"）时直接用服务器的；没有时由程序自己去读取网页来生成。读取网页会让对方网站看到你的 IP 地址，如果介意可以在设置 › Link Previews 里关掉，关掉后卡片只显示链接文字和网站名。夹在句子里的链接、视频链接（已有缩略图）和上传的文件保持原样。
- **图片有预览时不再显示链接**：发出的图片只显示图片本身，下面的文件链接不再重复出现；和图片一起发的文字照常显示，其他文件（比如 PDF）的链接也保留。

**还需要你反馈**：更新后启动时是否弹出了允许通知的提示，设置里的通知状态是否正确、测试通知能否收到；较大的截图拖进去能否上传成功；图片下面的链接是否已经不见了；链接卡片的样子是否符合你的预期。
