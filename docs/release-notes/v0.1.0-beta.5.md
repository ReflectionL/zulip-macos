## 修复（Fixes）

- **私信、频道和话题有时加载不出来（这次换了思路）**：前几版只修了"刷新话题列表挡路"，这次查到所有会话共用的加载路径上还有几处会让打开会话排队：
  - 登录和重连时，登录请求、注册事件队列、拉取所有频道的话题列表都在同一个核心线程里依次完成，期间点开的会话要等它们全部结束。现在登录放到旁边去做，缓存的会话和草稿立刻可用，需要联网的请求在登录完成后按顺序补上；话题列表先用缓存，服务器的在后台更新。
  - 发送、编辑、删除、表情回应、标星、标记已读也是在核心线程里等服务器回复的，一条慢请求会挡住后面所有操作。现在这些操作在后台执行，发送仍保持先后顺序。
  - 界面这边，每次登录成功都会等钥匙串保存 API key；如果钥匙串卡住（比如弹出访问授权），之后所有新消息和会话内容都会排队。现在保存放到后台，钥匙串里本来就有同一个 key 时直接跳过。
  - 每条新事件都会把启动以来收到的全部消息整份传给界面，界面再在主线程上逐份处理，还每次重排整个用户列表，打开会话的结果要排在它们后面；开得越久越慢。现在只保留最新 1000 条，一阵事件只处理最新一份，用户列表没变就不重算。
  - 从一个已加载的会话直接切到另一个时，以前复用了上一个会话的滚动位置和输入框，可能停在空白处、看起来像没加载出来。现在每个会话都是全新的视图。
- **截图不显示（找到原因）**：带中文名的截图（比如"截屏2026-…png"）上传后，程序把服务器给的链接重新转码了一遍再放进消息。Zulip 只认原样的链接，于是服务器既不生成预览图、也不把文件关联到这条消息，别人那边也只看到一个链接。现在上传链接保持服务器原样；以前发出的、只有链接没有预览的图片，客户端会自己补上预览；图片临时下载地址拿不到时，改用账号凭据直接下载。
- **消息通知不推送（这次换了思路）**：
  - Mac 睡眠或网络中断后，服务器会丢掉旧的事件队列，程序会注册新的；但中间到达的消息不会出现在新队列里，所以从来不推送。现在重连后会主动拉取这段时间里的未读消息（最多 50 条）并补发通知。
  - 窗口在后台时，macOS 的 App Nap 可能让程序"打盹"几分钟，通知延迟，甚至让服务器判定队列失效。现在登录期间会阻止 App Nap（不影响 Mac 正常睡眠）。
  - 长轮询的超时时间和服务器的心跳间隔一样长，心跳刚到时请求可能被提前掐断。现在多留了 20 秒余量。
  - 系统设置里通知样式设成"无"时，程序会像通知被关闭时一样提示你；系统拒绝显示通知时，改为 Dock 图标跳动加提示音，不再悄无声息。
- **每个频道的 general chat 话题一直是小铃铛、改不了**：general chat 在 Zulip 里的话题名是空的，程序把空话题名当成非法输入拒绝了，所以关注 / 默认 / 静音都改不了。现在可以正常修改。小铃铛本身多半来自 Zulip 的"自动关注你发起或参与的话题"设置，现在你可以自己改回默认。

## 新功能（New features）

- **聊天界面改成 Element 风格**：
  - 同一个人连续发的消息归为一组，组的开头是头像，名字显示在头像正右边，并且每个人的名字有固定的颜色。
  - 下面每条消息各占一行。鼠标移到某条消息上时，这一行会变灰，左边头像那一栏会出现灰色小字显示时间；停留一下可以看到完整日期。操作按钮在右上角。
  - 每天的第一条消息上方有居中的日期分界线（今天显示 Today，昨天显示 Yesterday，更早的显示星期和日期）。

**还需要你反馈**：私信、频道和话题是否还会加载不出来，截图能否显示，通知是否能收到（尤其是 Mac 睡眠唤醒之后），general chat 的铃铛能否改掉，以及新的聊天界面是否符合你的预期。
